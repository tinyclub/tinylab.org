## Linux 内核最新消息

这周日（23 号）好像出了点小状况，Linus 竟然没有在这天发布点什么东西，而这位老先生在坚持他的周日发布方面一向是有着非常好的记录的。不过还好，我们在周一看到 Linus Torvalds 正式发布了 Linux 6.14 内核作为最新的稳定版本。

Linux 6.14 提供了许多令人兴奋的新功能，例如 NTSYNC 驱动程序，它用于模拟 Windows NT 的同步原语以增强 Wine / Steam Play 游戏性能，AMDXDNA 加速器驱动程序主要用于在 Linux 下启用 Ryzen AI NPU，许多其他 AMD 和 Intel 增强功能，开源图形驱动程序的持续工作， 更多 Rust 编程语言抽象，等等。

Linux 6.14 将被 Ubuntu 25.04、Fedora 42 和其他 2025 年春季 Linux 发行版所采用。

现在又进入 Linux 6.15 合并窗口期，这是一个非常令人兴奋的新版本，并且已经有许多早期的拉取请求在等待处理。

## Linux 将与 zstd 1.5.7 同步

> The Zstandard (Zstd) compression code sadly hasn't been regularly synced with the latest upstream Linux kernel sources but a patch posted this evening goes ahead and syncs the in-kernel Zstd code against the Zstd 1.5.7 state.

目前有个不好的现象，就是 Zstandard （Zstd） 压缩代码没有做到定期与最新的上游 Linux 内核源同步，但本月中我们看到了一组补丁，这组补丁计划将内核里的 Zstd 代码升级到 Zstd 1.5.7。

来自 Meta/Facebook 的 Nick Terrell 提交了这组补丁。除了带来一些性能改进和其他增强功能外，Intel 工程师一直希望此内核内更新能够公开 Zstd API，以允许 QAT 加速，从而加快 Zstd 的 LZ 匹配查找。这反过来可以在支持 Intel QAT 的硬件上产生额外的性能优势。

使用 Zstd 和这个新更新的代码进行 Btrfs 压缩的基准测试显示了在一系列压缩和解压缩测试中有一些效率提升，但也有一些性能回退。

希望这组补丁能在 6.15 合并窗口中进入主线。

新闻出处，“Linux Patch Posted For Syncing The Kernel Code With Zstd 1.5.7”: <https://www.phoronix.com/news/Linux-Zstd-1.5.7-Patch>。

**关键词**: Linux, Zstd

## Linux 内核的 zstd 代码新添了一位共同维护者

> Hopefully leading to more timely updates to the Zstd compression code within the Linux kernel is a decision to add on a co-maintainer of the in-kernel Zstandard code.

由于希望在 Linux 内核中更及时地更新 Zstd 压缩代码，所以有必要增加内核 Zstandard 代码的共同维护者。

虽然最近内核内代码也更新到了 Zstd 1.5.7，但对 Linux 内核中 Zstd 的更新一直很少。即使越来越多的 Linux 文件系统使用 Zstd 进行透明文件压缩、Zstd 模块压缩和其他 Zstd 压缩/解压缩使用，内核树中的 Zstd 代码也落后于上游 Zstd 源。很多时候已经过时了。

来自 SUSE 的 David Sterba 以其在 Btrfs 上的开发工作而闻名，他将加入内核 Zstd 代码的共同维护者队伍，希望这能帮助解决上面我们提到的问题。

Sterba 提交了一份补丁, 更新了 MAINTAINERS 条目，在补丁中他说：“最近，由于去年缺少更新，ZSTD 树已从 linux-next 中删除。由于内核中的 ZSTD 用户很多，因此我们需要保持代码的维护和更新。我将充当备份，将 ZSTD 同步到 linux，Nick 对此也表示同意。”

Meta 的工程师 Nick Terrell 对他的帮助表示感谢，并承认他并不总是最投入 Linux 内核开发活动的人，因此在 Sterba 的共同维护下，有望对内核中 Zstd 的发展带来更好的未来。

新闻出处，“Linux Kernel's Zstd Code Gets A Co-Maintainer”: <https://www.phoronix.com/news/Linux-Zstd-Co-Maintainer>。

**关键词**: Linux, Zstd

## Linux 6.15 中将出现一个新的子系统 FWCTL 

> Assuming no objections from Linus Torvalds, the now open Linux 6.15 merge window could introduce a brand new subsystem: fwctl.

假设 Linus Torvalds 没有反对意见，Linux 6.15 合并窗口期间将可能会引入一个全新的子系统：fwctl，它是 firmware control 的缩写。

firmware control 子系统旨在帮助在越来越多的驱动程序和硬件中标准化和建立通用规则，这些驱动程序和硬件将安全固件接口暴露给用户空间。

该子系统是由来自 NVIDIA 的 Jason Gunthorpe 提交的。据他在补丁中介绍，“fwctl 是一个新的子系统，旨在为将安全固件接口直接暴露给用户空间的日益增长的模式带来一些通用规则和秩序。与 RDMA/DRM/VFIO/uacce 等现有位置公开设备以进行数据路径作不同，fwctl 专注于设备的调试、配置和配置。它不会具有支持数据路径所需的功能，例如 interrupt delivery。这个概念类似于 “HW” RAID 空间的长期做法，即使用特定于设备的杂项设备来管理 RAID 控制器固件。fwctl 概括了这种配套调试和管理接口的概念，它与在适当子系统中实现的数据平面一起。“

除了初始 fwctl 子系统代码之外，该子系统还有三个初始驱动程序：CXL、NVIDIA Mellanox MLX5 和 AMD Pensando Smart NIC。

新闻出处，“New FWCTL Subsystem Submitted For Linux 6.15”: <https://www.phoronix.com/news/Linux-6.15-fwctl>。

**关键词**: Linux, firmware control Subsystem

## Linux 6.15 CRC 代码应该会看到 Intel/AMD AVX-512 CPU 的大幅加速

> While we are still awaiting the Linux 6.14 release (or a 6.14-rc8 release) with no kernel drop having occurred on Sunday, early pull requests for the Linux 6.15 kernel cycle continue flowing in. Among the early pull requests over the weekend were the CRC code updates that include some nice optimizations for those running on AVX-512 processors.

来自 Google 的 Eric Biggers 在本周日提交了针对 Linux 6.15 的 CRC 更新。此 PR 包括对 CRC64 循环冗余校验代码的修改。最令人兴奋的是重写了针对 x86 PCLMULQDQ 优化的 CRC 代码并添加了 VPCLMULQDQ 支持。这还包括 crc64_be 和 crc64_nvme 代码的加速。

Eric Biggers 在之前的补丁系列中解释了循环冗余校验代码中的这种 VPCLMULQDQ 用法：“这种方法允许轻松连接 CRC-8、CRC-16、CRC-32 或 CRC-64 的任何变体的 x86 优化实施，包括对 VPCLMULQDQ 的全面支持。在长消息上，生成的函数比现有的 PCLMULQDQ 优化函数（如果存在）快 4 倍，或比现有的基于表的函数快 29 倍。” 这的确是一个重大的性能改进。

新闻出处，“Linux 6.15 CRC Code Should See Big Speed-Ups For Intel/AMD AVX-512 CPUs”: <https://www.phoronix.com/news/Linux-6.15-CRC>。

**关键词**: Linux, CRC

## Linux 6.15 将支持 Airoha NPU，一款 RISC-V 网络处理器

> Intel has been running an annual open-source developer survey and they recently wrapped up their survey for 2024 and today published the results to provide various insight into the health of open-source development.

Linux 6.15 内核合并窗口之前，net-next 中加入了对 Airoha NPU 的支持，不要与当今流行的 Neural Processing Unit（NPU）混淆，Airoha NPU 是一款 Network Processor Unit。

Airoha NPU 是 Airoha EN7581 SoC 中的 RISC-V 模块，用于有线和无线硬件流卸载数据包处理器引擎（PPE）。EN7581 系列 SoC 是一款四核 ARM CPU，具有 8 核 RISC-V 网络处理器（“NPU”），可提供 WAN、WLAN WiFi 6 / WiFi 7 和 LAN 处理以及智能数据包加速。该 SoC 旨在用于 10G-PON 住宅和企业网关。

新闻出处，“Linux 6.15 To Support The Airoha NPU - A RISC-V Network Processor Unit”: <https://www.phoronix.com/news/Linux-6.15-Airoha-NPU>。

**关键词**: Linux，Airoha，NPU, RISC-V

## 软银收购 ARM 服务器 CPU 供应商 Ampere Computing

> SoftBank Group just announced they will be acquiring Ampere Computing, the leader in ARM64 server processors that has come under increasing pressure with more of the public cloud service providers like Google, Microsoft, and Amazon/AWS turning to their own in-house ARM64 server processor designs.

软银集团刚刚宣布他们将收购 Ampere Computing，后者是 ARM64 服务器处理器的领导者，随着越来越多的公共云服务提供商（如 Google、Microsoft 和 Amazon/AWS）转向他们自己的内部 ARM64 服务器处理器设计，该公司承受着越来越大的压力。

软银将以 65 亿美元的全现金交易收购 Ampere Computing。甲骨文和凯雷是出售其在 Ampere 股份的公司之一。他们预计这笔交易将于 2025 年下半年完成。

鉴于软银参与 Arm 并预计 Ampere Computing 将被收购，该公告并不令人惊讶......尽管许多人猜测，鉴于他们现有的关系，它最终会被 Oracle 收购。Ampere Computing 制造领先的 ARM64 服务器处理器，这些处理器很容易获得，尽管他们最近在远远落后于计划后难以大规模交付 AmpereOne，现在与最新的 AMD EPYC Turin 和 Intel Xeon 6 Sierra Forest 处理器竞争。目前围绕 Ampere Computing 硬件的大部分关注点仍然与多年的 Ampere Altra 设计有关。希望软银的收购将帮助 Ampere 制定更积极的未来路线图。

新闻出处，“SoftBank Acquiring ARM Server CPU Vendor Ampere Computing”: <https://www.phoronix.com/news/SoftBank-Acquiring-Ampere>。
